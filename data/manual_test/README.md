# Manual test guide — 2026-05-04 BCCT overhaul + LLM smart parser

5 fixture files + cleanup SQL for driving each of the 4 stages by hand
through the running web UI. Generated by `_generate.py`.

## Setup

```bash
# Server up (if not already)
uv run uvicorn app.main:app --port 8754 --host 127.0.0.1 --reload

# Login
http://127.0.0.1:8754/login
  email:    admin@data-hub.local
  password: admin123
  (role=dev — required for /admin/settings/technical)

# Wipe prior manual-test rows so you can re-run
psql -d data_hub -f data/manual_test/_cleanup.sql

# Re-generate fixtures (only needed if you change _generate.py)
uv run python data/manual_test/_generate.py
```

Use any existing client. Recommended: **Growatt VN** (`growatt-vn`)
because it already has 12 typed CO columns back-filled from real data;
the manual-test rows just add 3-4 more.

## Stage A+B — 12 CO columns + year derived

**File:** `01_stage_AB_full_co_bcct.xlsx`  (3 rows, full CO headers)

**What to test:**

1. Visit `http://127.0.0.1:8754/clients/growatt-vn/bcct/upload` →
   form has **only a file picker, no `Năm` field** (year derived
   per-row from `Ngày đăng ký`).
2. Upload `01_stage_AB_full_co_bcct.xlsx`.
3. Redirect to `/clients/growatt-vn/bcct`. 3 new rows added.
4. **Verify typed CO columns via API:**
   ```bash
   curl -H "Authorization: Bearer x" \
     "http://127.0.0.1:8754/v1/hub/bcct?client_id=growatt-vn&declaration_no=MAN_AB_001" \
     | python -m json.tool
   ```
   Expect every CO field populated: `exporter_name='CÔNG TY TNHH GROWATT
   NEW ENERGY VIETNAM'`, `consignee_name='ACME ENERGY GMBH'`,
   `incoterms='FOB'`, `weight=245.5`, `package_count=8`,
   `invoice_date='2026-03-10'`, `departure_date='2026-03-16'`,
   `destination_code='DEHAM'`, `transport_mode='1'`,
   `exchange_rate=25400`, `year=2026` (derived from registration_date).
5. **Verify year is GENERATED:** rows from 2026-03 → year=2026; the
   row dated 2026-03-25 → year=2026. The DB computes this; the form
   never asks.

## Stage D — LLM-driven smart parser fallback

**File:** `02_stage_D_chinese_headers.xlsx`  (2 rows, headers in Chinese)

**Prerequisite:** LLM configured. Visit
`http://127.0.0.1:8754/admin/settings/technical` (dev-only). Paste:

```
Base URL:   https://api.anthropic.com/v1   (or https://api.openai.com/v1)
Model:      claude-sonnet-4-6                (or gpt-4o-mini)
API Key:    sk-ant-...                       (Anthropic OAI shim) or sk-...
Temperature: 0.0
Max calls / day / client: 50
```

Submit. The settings persist in `hub.app_settings`.

**What to test:**

1. Upload `02_stage_D_chinese_headers.xlsx` to
   `/clients/growatt-vn/bcct/upload`.
2. Rigid parser rejects (no header alias matches `报关单号` /
   `登记日期`). Hub computes file_signature, looks up cache (miss
   first time), calls LLM.
3. Redirect to `/clients/growatt-vn/bcct/parse-mapping/{upload_id}`.
4. Page shows the LLM's proposed mapping per column with sample data:
   ```
   Header in file        Logical field        Sample data
   报关单号              declaration_no       MAN_D_001 · MAN_D_002
   登记日期              registration_date    2026-04-01 · 2026-04-05
   海关编码              customs_code         ZH-INV-3000 · ZH-INV-5000
   …
   ```
5. Review each row, edit if wrong, submit.
6. Mapping saved to `hub.parser_mappings` (keyed by
   client+module+file_signature). Rows ingested.
7. **Verify cache hit on second upload:** re-upload the same file →
   no LLM call this time (cache hit). Should land directly without
   the proposal page.
8. **Verify cross-client isolation:** upload the same file to a
   different client (e.g. `dke-vietnam-d0e3`) → cache miss → LLM
   called again (file_signature includes client_id).

**Without LLM configured:** upload returns 400 with the new sanitized
error: "Parse error and LLM proposal failed. Check server logs or try
another file. (Detail withheld to avoid leaking credentials.)" — by
design (post-/rev fix).

## Stage C1 — Confirm-on-update gate

**Files:** `03a_stage_C1_baseline.xlsx` then `03b_stage_C1_changed.xlsx`

**What to test:**

1. Upload `03a_stage_C1_baseline.xlsx` to
   `/clients/growatt-vn/bcct/upload`. 3 NEW rows
   (MAN_C1_A/B/C, all qty 100/200/300). Direct apply, no preview.
2. Upload `03b_stage_C1_changed.xlsx`. Hub classifies:
   - `MAN_C1_A` quantity 100 → 88 = **DIFF**
   - `MAN_C1_B` identical = **NOOP**
   - `MAN_C1_C` missing from file = **ORPHAN candidate**
   - `MAN_C1_D` not in DB = **NEW**
3. Redirect to `/clients/growatt-vn/bcct/upload/preview/{pending_id}`.
4. Preview shows: 1 NEW · 1 NOOP · 1 DIFF · 1 ORPHAN.
5. **Critical regression case** (post-/rev): tick *only* "Xác nhận
   xóa orphan", leave the DIFF checkbox unticked. Submit.
   - Expected: MAN_C1_A still has qty=100 (preserved). MAN_C1_C
     deleted. MAN_C1_D inserted.
   - The bug we fixed would have ALSO deleted MAN_C1_A (data loss).
6. **Verify via psql:**
   ```sql
   select transaction_key, line_no, quantity from hub.bcct_rows
   where transaction_key like 'MAN_C1%' order by transaction_key;
   ```
   Should show A=100, B=200, D=400. C absent.
7. **Idempotency:** copy the preview URL, open it in a second tab,
   click submit there too. Second click 404s ("Pending upload not
   found or already applied") because the pending row was DELETE'd
   in the same tx as the apply.

## Stage C2 — History page + ops bypass CLI

**No new file needed** — uses rows from Stage C1.

**What to test:**

1. After Stage C1 finishes, visit
   `http://127.0.0.1:8754/clients/growatt-vn/bcct/history/MAN_C1_A-1/1`
   (transaction_key is `MAN_C1_A-1` because the parser sets
   `txn_key = "{decl_no}-{line_no}"`).
2. Page lists every UPDATE/DELETE event for this row, with:
   - timestamp
   - actor (`changed_by` from session GUC — should be `admin@…`'s
     user_id)
   - action (`update` / `delete`)
   - which fields changed
   - upload_id reference

3. **Ops bypass via CLI:**
   ```bash
   uv run python scripts/bcct_force_apply.py \
     --client growatt-vn \
     --file data/manual_test/03b_stage_C1_changed.xlsx \
     --dry-run
   ```
   Output shows NEW/NOOP/DIFF/ORPHAN counts; nothing applied.

   Apply for real:
   ```bash
   uv run python scripts/bcct_force_apply.py \
     --client growatt-vn \
     --file data/manual_test/03b_stage_C1_changed.xlsx
   ```
   No web confirm gate — the CLI bypasses it. Audit trigger captures
   `changed_by='ops:script'` in `hub.bcct_row_history`.
4. **Verify ops actor in history:** revisit the history page; the
   newest event row should show `ops:script` in the actor column.

## Reset between runs

```bash
psql -d data_hub -f data/manual_test/_cleanup.sql
```

This wipes manual-test rows + history + pending + LLM-proposed mappings
+ the file_upload audit rows for these fixtures, but leaves
`app_settings` (your LLM keys stay) and other clients' real data alone.
