# Data Hub API Request: Declaration File Status

## Use Case
CO needs the TKX/TKN tab to tell operators whether each referenced export/import declaration has an uploaded declaration file. The status must answer "có tờ khai hay thiếu tờ khai", not whether the declaration has BCCT rows.

## Existing Endpoint Gap
- `GET /v1/hub/bcct` and `GET /v1/hub/bcct/invoice-matches` expose BCCT declaration rows. They prove BCCT row presence only, not declaration-file presence.
- `GET /api/v1/clients/{client_id}/declarations` exposes `file_count`, but it is cookie-session protected and returns `401 login required` to CO's service-token Bearer caller. CO should not depend on this cookie-only route.

## Proposed Contract
Method and path:
`GET /v1/hub/clients/{client_id}/declarations`

Query parameters:
- `direction`: optional; `import` or `export`.
- `declaration_nos`: optional comma-separated declaration numbers. When omitted, return paginated declaration summaries.
- `has_files`: optional; `yes` or `no`.
- `cursor`: optional pagination cursor.
- `limit`: optional integer, max `500`.

Request body:
None.

Response body:
```json
{
  "items": [
    {
      "declaration_no": "308449399330",
      "direction": "export",
      "bcct_line_count": 2,
      "file_count": 1,
      "earliest_bcct_date": "2026-04-21"
    }
  ],
  "next_cursor": null
}
```

Error cases:
- `400 invalid_direction` when direction is not `import` or `export`.
- `400 invalid_has_files` when has_files is not `yes` or `no`.
- `401 bearer token required` when auth is missing or invalid.
- `403 forbidden` when the token cannot view the client.
- `404 client not found`.

## Auth
Required scope:
`hub:read`

Client scoping rule:
Service-token `client_ids` whitelist must include `{client_id}` when present.

Token type:
User JWT or service token.

## Data Semantics
Source of truth:
`hub.customs_declaration_files` for `file_count`; BCCT rows only provide the declaration list and line count.

Precision requirements:
Declaration numbers are exact strings after Data Hub's existing declaration normalization. Direction is part of identity: `(client_id, declaration_no, direction)`.

Pagination:
Cursor pagination compatible with existing `/v1/hub` list endpoints. When `declaration_nos` is provided, return all requested matches up to the maximum request size and no cursor.

Idempotency:
Read-only.

Versioning or pinning:
No case snapshot pinning required. CO uses this as a live completeness check before dossier export.

## Tests Required In Data Hub
Provider tests:
- Bearer service token with `hub:read` can list declaration summaries and sees `file_count`.
- `declaration_nos` filters exact requested declarations across import/export.
- `has_files=yes/no` filters by `file_count`.

Negative tests:
- Missing/invalid bearer returns `401`.
- Service token without client access returns `403`.
- Invalid direction returns `400`.

Edge cases:
- Declaration exists in BCCT but has zero uploaded files.
- Declaration has multiple uploaded files.
- Same declaration number exists in both import and export directions.

## Related Web Download Route
CO also needs a cookie-session Data Hub route for operators to download all uploaded declaration files for a selected C/O shipment:

Method and path:
`GET /clients/{client_id}/declarations/download.zip`

Query parameters:
- `direction`: required; `import` or `export`.
- `declaration_nos`: required comma-separated declaration numbers.
- `filename`: optional suggested archive filename.

Behavior:
- Requires a logged-in Data Hub user who can view `{client_id}`.
- Redirects unauthenticated users to `/login?next=...`.
- Downloads one ZIP archive containing all matching uploaded declaration files from `hub.customs_declaration_files`.
- Files inside the ZIP must be at the archive root level, not grouped into declaration subfolders.
- Duplicate original filenames should be made unique safely.
- The ZIP must include `DANH_SACH_TO_KHAI.txt` listing every requested declaration, whether it has files, whether it is missing files, file counts, and included filenames.
- If no files match, still return a ZIP with the manifest and a small marker file such as `NO_FILES_FOUND.txt`.

Expected filenames generated by CO:
- Export declarations: `TKX_<shipment_export_declaration_no>.zip`
- Import declarations for the C/O shipment: `TKN_CO_<shipment_export_declaration_no>.ZIP`

## CO Consumer Plan
Adapter method to add in `app/data_hub_client.py`:
`list_declarations(client_id: str, *, direction: str | None = None, declaration_nos: list[str] | None = None) -> list[dict]`

Call sites that will consume the adapter:
- `DataHubPortfolioService.co_case_source_context()` should populate `source_context["declaration_file_counts"]`.
- `case_tkx_tkn_summary()` already accepts `declaration_file_counts` and uses it for `in_data_hub`.
- `export_co_case_dossier_zip()` should use the same context for `tkx-tkn.json`.

Consumer tests:
- TKX/TKN status stays missing when BCCT rows exist but `file_count == 0`.
- TKX/TKN status is present when `file_count > 0`.
- Missing counts in the exports tab and review checklist reflect declaration-file presence.
