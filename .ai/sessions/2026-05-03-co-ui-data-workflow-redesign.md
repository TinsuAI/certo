# 2026-05-03 CO UI Data Workflow Redesign

## What Was Done
- Reworked shared data tables for compact operations:
  - added namespaced filters/search/pagination query handling in `app/table_view.py`
  - updated `_advanced_table.html` for compact toolbar metadata, passthrough params, and link-cell rendering
- Rebuilt the BOM view so the user starts from finished products and then sees the BOM lines for the selected product.
- Simplified C/O case entry:
  - index page now focuses on creating/opening a case, not dashboard KPIs
  - create flow asks for invoice first, then searchable market
  - market selection previews the suggested form and instrument
  - persisted case records infer form/agreement/rule defaults from destination market
- Added source-backed form guidance presets:
  - Form B: `05/2018/TT-BCT`, amendments `44/2023/TT-BCT` and `23/2025/TT-BCT`
  - CPTPP: `03/2019/TT-BCT`
  - EUR.1: `11/2020/TT-BCT`, amendment note for `41/2022/TT-BCT`
  - AI: `15/2010/TT-BCT`
  - common markets include EU, Japan, Canada, Australia, and India
  - HS preview mappings were added for common 8504/8541 cases
- Connected invoice-matched BCCT export rows into C/O guidance/origin context so product HS codes can show criteria preview by form/instrument.
- Removed origin-tab workbook upload controls. The origin tab now states that criteria are system-generated from invoice, BCCT export rows, form/instrument, and BOM snapshot.
- Added a view-only demo preload for the origin tab. If a case has no products and no invoice-matched BCCT rows, the tab shows 2 Growatt demo finished products and 4 demo material rows, clearly labeled `Demo tự nạp`.
- Added screenshot artifacts under `.ai/screenshots/co-data-ui-redesign/` for desktop/mobile C/O flow, BOM, and origin checks.
- Added tests covering:
  - C/O index/searchable market flow
  - invoice -> BCCT product -> HS criteria guidance
  - origin tab no longer exposes upload/seed controls
  - origin tab demo preload does not silently carry into review/export context

## Decisions Made
- Kept the UI compact and operator-oriented instead of card-heavy:
  - no large hero or KPI dashboard on C/O case index
  - case list is a compact list rather than a wide table
  - origin header is a source strip, not an upload panel
- Used a small built-in searchable combobox instead of adding a new JavaScript dependency.
- Kept form/legal presets centralized in `app/co_forms.py`; templates only render the context.
- Kept the origin demo as context-only, not persisted state. It is useful for UI inspection but cannot be mistaken for a real uploaded criteria workbook.
- Preserved the existing upload route `/clients/{client_id}/upload` for legacy tests/parser behavior, but removed it from the C/O origin UI.
- Committed screenshot artifacts because this project already tracks UI screenshots under `.ai/screenshots/` and the session involved visual review.

## What Didn't Work
- The first C/O case index still looked like an admin table with too many columns; it was replaced with a simple create panel and compact case list.
- A datalist was not enough for the requested searchable dropdown behavior; it was replaced with a small combobox that filters the preset market buttons.
- The origin tab originally had `Upload và parse` and seed XLSX links. The user clarified this was conceptually wrong because the criteria table must be generated by the system, so those controls were removed.
- A temporary screenshot server was started on port `8002`; it was stopped after screenshots. The primary dev server on `8001` remains.
